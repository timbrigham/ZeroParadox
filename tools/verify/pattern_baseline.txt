# Every DETECTION PATTERN this suite advertises. One section per checker.
# Each checker's `--selftest` asserts its live pattern set is a SUPERSET of its section.
#
# WHY (PAT-1, 2026-08-16). The scope pins answer "did the checker look at everything". Nothing
# answered "would it recognise anything". Measured by mutation -- replacing each advertised pattern
# with a string that cannot match, one at a time, then re-running that checker's own --selftest --
# **30 of 34 patterns were SILENT**. Deleting `artifact` from check_modal's list stops it catching
# the defect class it was built for, with --selftest green, --block exit 0, and check_checkers
# reporting all four properties satisfied.
#
# A must-fire control only proves the patterns it happens to exercise. There were 3 controls for 14
# phrases.
#
# ⚠ THE CONTROLS CANNOT BE GENERATED FROM THE LIVE LIST. A control derived from the pattern list
# vanishes together with the pattern it guards, so deletion stays silent and the design defeats
# itself. The pin must be an INDEPENDENT record. That is this file.
#
# SUPERSET: adding a pattern is free, only a REMOVAL fires. Weakening a detector must never be
# quiet; strengthening one must never be obstructed. To retire a pattern deliberately, delete its
# line here in the same change -- a reviewable act, and this file is in `batch.CHECKERS`.
#
# ⚠ NOT a suppression baseline. Nothing here is a grandfathered defect. Do not count it as debt.
